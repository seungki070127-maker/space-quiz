# 게임 기획 (1페이지 기획서)

## 개요
코드부터 쓰면 "재미없는데 고치기 어려운" 게임이 된다. 구현 전에 **1페이지 기획서**를 만들고 사용자 확인을 받는다.

## 절차
1. 아이디어에서 빠진 핵심만 질문한다 (한 번에 1~2개). 이미 답이 있는 건 묻지 않는다.
2. 아래 형식으로 기획서를 채워 사용자에게 보여준다.
3. 사용자가 확정하면 `docs/game-design.md`에 저장하고 구현 단계(`game-loop` 스킬)로 넘어간다.

## 기획서 형식
```markdown
# <게임 이름> 기획서
## 한 줄 소개
- 누가, 무엇을, 왜 재미있는가.
## 핵심 루프 (10초 단위로 반복되는 행동)
- 보기 → 판단 → 입력 → 결과 피드백 → 보상
## 규칙
- 목표 / 승리 조건 / 패배 조건 / 점수 계산
## 조작
- 키보드: … / 마우스·터치: …  (둘 다 필수)
## 진행·난이도
- 시간·단계에 따라 무엇이 어려워지는가
## 화면 상태
- 타이틀 → 플레이 → 일시정지 → 게임오버/결과 → 재시작
## 범위
- MVP(첫 버전에 반드시): …
- 나중에(하지 않음): …
```

## 원칙
- **MVP는 작게**: 메카닉 1개, 화면 상태 4개 이하. 나머지는 "나중에"로.
- 모든 규칙은 숫자로 (예: "빠르게" ✗ → "초당 120px" ✓). 이 숫자들이 그대로 `CONFIG` 데이터가 된다.
- 프로젝트 규칙(AGENTS.md) 준수: 단일 `index.html`, 외부 의존성 없음, 한국어 UI, 키보드 접근성.
- 이 저장소에서 기존 퀴즈를 바꾸는 기획이면 현재 동작 중 유지할 것을 명시한다.

## 흔한 실수
| 실수 | 대처 |
|------|------|
| 기능 목록만 있고 핵심 루프 없음 | 10초 반복 행동부터 정의 |
| 패배 조건 없음 | 긴장감이 없다 — 시간·목숨·실수 횟수 중 하나 |
| 터치 조작 누락 | 모바일에서 플레이 불가 — 조작 항목에 반드시 기재 |
| MVP에 모든 것 포함 | "나중에" 섹션으로 과감히 이동 |

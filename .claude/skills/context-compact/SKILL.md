# 컨텍스트 압축

## 개요
대화를 버리지 않고 **같은 세션 안에서** 용량만 줄인다. 핵심을 전보체 요약으로 뽑고, 그 요약을 지시문으로 넣은 `/compact` 명령을 사용자에게 건넨다.

모델은 `/compact`를 직접 실행할 수 없다. 실행은 사용자 몫.
대화를 통째로 비우고 새로 시작하려면 → `context-reset` 스킬 사용.

## 절차
1. `git status`, `git log --oneline -3`으로 실제 상태 확인. 기억과 다르면 git 기준.
2. 대화 전체를 훑어 아래 **보존 / 폐기** 기준으로 분류.
3. 아래 형식의 요약을 채팅에 출력 (파일 저장 안 함).
4. 마지막 줄에 사용자가 그대로 복사할 `/compact` 명령 제시.

## 보존 / 폐기
| 보존 | 폐기 |
|------|------|
| 사용자 요청 원문 핵심어 | 인사, 확인 응답, 사과 |
| 사용자가 확정한 결정·선호 | 결정 전 검토했다 버린 대안 |
| 변경 파일:줄, 커밋 해시, 브랜치, PR 링크 | 파일 전체 내용, 긴 diff |
| 현재 오류 메시지 핵심 한 줄 | 이미 해결된 오류의 로그 |
| 남은 할 일, 막힌 이유 | 도구 호출 과정 서술 |
| 프로젝트 규칙(AGENTS.md 등) 중 이번 작업 관련분 | 다시 읽으면 되는 문서 본문 |

## 출력 형식 (이 순서, 이 제목 그대로)
```markdown
## 압축 요약
- 목표: 사용자 요청 한 줄.
- 상태: 브랜치 X. 최신 커밋 abc1234. 미커밋 변경 없음.
- 완료: 항목; 항목; 항목.
- 결정: 사용자 확정 사항.
- 남음: 1) 구체 행동 2) 구체 행동.
- 주의: 제약·막힘. 없으면 "없음".

/compact 위 "압축 요약"의 목표·상태·완료·결정·남음·주의만 전보체로 보존. 도구 출력, 파일 내용, 해결된 오류, 폐기된 대안은 버림.
```

### 전보체 규칙
- 항목당 한 줄. 조사·어미 최소화, 명사형/`~함`·`~완료` 종결.
- 요약 전체 15줄 이내. 넘치면 `완료`를 세미콜론으로 병합.
- 비밀값 기록 금지. 위치만.

## 흔한 실수
| 실수 | 대처 |
|------|------|
| 요약만 하고 `/compact` 명령 누락 | 마지막 줄에 반드시 명령 제시 |
| 사용자 결정 누락 → 압축 후 재질문 | `결정` 줄 필수 |
| "남음"이 모호("마무리") | 바로 실행 가능한 행동으로 |
| 파일 내용·로그를 요약에 붙여넣음 | 파일:줄, 핵심 한 줄로 대체 |
| 압축 대신 초기화가 맞는 상황 | 주제 전환·새 작업이면 `context-reset` 안내 |
